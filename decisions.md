# TextureText — Decisions & Custom CSS Log

## User Clarifications (2026-10-26 – 2026-10-27)

| # | Area | Decision |
|---|---|---|
| U1 | Text layout engine | Use `npm @chenglou/pretext` (not a hand-rolled engine). Effort goes into the luma-shape engine and rendering. |
| U2 | Flow mode | Support both wrap directions (text in dark areas / text in bright shape), switchable at runtime. |
| U3 | Input text | Editable textarea in the UI with a bundled default text; re-prepares on change. |
| U4 | Export content | Text and background have individual color selectors; the text layer composes over the processed source with a blend-mode dropdown (`none` by default). |
| U5 | ProRes capture | Both: deterministic frame-by-frame render (video restarts at t=0) for video/image sources; live start/stop record for webcam. |
| U6 | Stage layout | Overlay: the text layer composes with blend modes over the processed source in one view. |
| U7 | Dev port | Port `5190` with `strictPort` (5174/5175 are used by TextureMosaic's servers; Playwright's `reuseExistingServer` otherwise attaches to the wrong app). |
| U8 | TextureMosaic UI parity | Match the exact layout and style of `TextureMosaic` (`src/ui/terminal.css`, `src/ui/styles.css`, `src/ui/app-ui.ts`): `#app` 3-column studio grid (`319px 1fr 270px`), `--ts-*` Figma tokens, `JetBrains Mono`, `.ts-*` component system, `.toast.is-danger` error toast, and focused-input preservation during live frames. |
| U9 | Stage content (Tweak) | Center stage shows only the flowed text over `bgColor`; control-map media elements (`#stageVideo` / `#stageImage`) stay hidden off-stage and feed only the processed Inputs preview and the luma field. |
| U10 | ProRes export button (Tweak) | `export prores` button lives in the stage header next to `snapshot png`; profile / sec / fps settings remain in the right `export` parameter group. |
| U11 | Resolution selector (Bugfix) | Stage box was sized by CSS `aspect-ratio` + `width: 100%` (broken by `max-height` clamp) and the text layer never re-scaled for static sources because the `ResizeObserver` didn't trigger a re-render. Fixed: `domRenderer` computes the contain-fit box from the stage container (ResizeObserver-driven, no hot-loop DOM reads), sizes the stage and scale-transforms the text layer, and re-paints on container resize. Regression test in `tests/e2e/bugfixes.spec.ts`. |
| U12 | Mixed line styles (Bugfix) | `domRenderer` restyled lines only when `i >= pool.length`, so pool elements hidden by a previous render kept stale styles when re-shown without a style change. Fixed: restyle from `lastRenderedCount` (previous visible count), or from 0 on any font/line-height/color change. All visible lines always share the current style. Regression test in `tests/e2e/bugfixes.spec.ts`. |
| U13 | Blend modes compose over the source (Bugfix) | Stage media elements were fully hidden (overcorrection of U9), so blends only affected text over the plain background. Fixed: `#stageVideo` / `#stageImage` render as the stage backdrop (`z-index: 1`) under the `mix-blend-mode` text layer; the processed control map stays in the Inputs preview thumbnail only (U9). PNG/ProRes canvas exports draw the same source frame (cover-fit) before the blended text, keeping D12 parity. `tests/e2e/step1.spec.ts` visibility assertions updated (behavior change, logged per §8.4). |
| U14 | Post-processed composition layer (Rework of U13) | The composed image is always the **post-processed** source: grayscale luma with `invert`/`contrast`/`offset`, quantized to the `grid px` × `lineHeight` grid cells — the exact canvas that shapes the text. It drives the Inputs preview thumbnail (`image-rendering: pixelated`) and the stage overlay `#stageProcessedCanvas`. Raw media (`#stageVideo`/`#stageImage`) stay hidden always (decoders only). Layering: `bgColor` stage background → text layer (`textColor`, normal blend) → post-processed overlay with `mix-blend-mode`. With `blendMode === 'none'` the overlay is hidden, so only `bgColor` + text are visible; any active blend mode composites the post-processed image over the text. PNG/ProRes exports replicate the same stack on canvas (`source-over` text, then the processed image with `globalCompositeOperation`). `step1.spec.ts` media assertions flipped back to hidden; `bugfixes.spec.ts` composition test rewritten (overlay visibility, blend mode, overlay pixels at working resolution). |
| U15 | Full-scene JSON presets | Ported the TextureMosaic preset system (its U11): `src/engine/presets.ts` with `TextureTextPresetV1` (name, canvas size, text, all 4 param groups, export settings, source slot with Base64-embedded media; webcam → PNG frame fallback restored as image), repo presets auto-discovered from `presets/*.json` via Vite `import.meta.glob` (lazy `?url` fetch), session presets, and the Parameters-panel `presets` group (dropdown / name / save / import / export). Ships `presets/defaultScene.json`. Debug API gains `exportPreset` / `importPreset`. Note: embedded videos make large `.json` files (same tradeoff as TextureMosaic). |
| U16 | Default boot preset + `?preset=` deep link | The app now opens with a repo preset applied instead of the bare built-in scene: `DEFAULT_PRESET_ID = 'pyramid1'` (`presets/pyramid1.json` — 1280×1280, embedded mp4, color-dodge blend). `resolveBootPresetId(search)` reads `?preset=`: absent → the default preset, `none`/empty → built-in default scene, any other id → that repo preset. `appUi` applies it through the same `applyRepoPreset` path as the dropdown (parsed JSON cached, so selecting the same preset later does not refetch 5.6 MB), then syncs the dropdown to `repo:<id>` and the name field to the preset name. Fetch/decode failures surface as the usual error toast and fall back to the built-in scene. |
| U17 | Preview staleness + static-frame smoothing (Bugfix) | Two regressions surfaced by the new default scene: (1) `preview` subscribed to `emit()` ahead of `syncControls`, so it drew the luma canvas from the **previous** emit — one frame behind every parameter change. `runReflow` now owns the refresh via a `refreshPreview` callback passed from `main.ts`, so the preview always shows the current frame. (2) `temporalSmooth` was applied to static images and paused video, so an invert/contrast change only moved the field 70 % of the way and stayed there. Smoothing is now applied only while a video/webcam is actually playing. `step1.spec.ts` invert/contrast assertions pass again. |

## Custom CSS Additions Log (spec §7 Rule 1)

`letieu/terminal.css` v0.0.4 (vendored at `src/ui/terminal.css`) provides base terminal variables, typography, `.button`, `.control`, `.input`, `.textarea`, `.select`, `.progress`, `.toast`, `.tag`, and `.title`. Inherited from `TextureMosaic` (`src/ui/styles.css`) and extended for TextureText:

1. **App 3-column studio grid (`#app`, `.ts-panel-inputs`, `.ts-panel-stage`, `.ts-panel-params`):** Fixed left `Inputs` column (`319px`, `#050505`), flexible center `Stage` + `Playback` column (`#0d0d0d`), and fixed right `Parameters` column (`270px`, `#050505`, scrollable).
2. **Source Input Block & Thumbnail (`.ts-source-block`, `.ts-source-grid`, `.ts-source-buttons`, `.ts-source-preview`):** `126px 96px` side-by-side grid with vertical `21px`-high `.button`s (`webcam` / `video file` / `image file`) on the left and a `96×96` square preview container on the right with `MEDIA_GLYPH_SVG` + cyan `add image` empty state, `.is-loaded` cyan border, cover-cropped processed preview canvas, and `.ts-preview-badge` filename.
3. **Text Input Container (`.ts-stack-container`, `.ts-text-area`):** Full-height bordered container in the left `Inputs` column with `.is-loaded` cyan border holding the editable fixed-text `<textarea>` plus `reset text` and `clear` actions.
4. **Center Stage & Stats Overlay (`.ts-canvas-stage`, `.ts-render-canvas`, `.ts-stage-media`, `.ts-stage-empty`, `.ts-stats-overlay`):** Aspect-fitted stage frame (`border: 1px solid #666666`, `#000000` background) with toggleable cyan-bordered monospace HUD (`FPS`, `FRAME`, `SOURCE`, `RES`).
5. **Playback Transport (`.ts-playback`, `.ts-transports`, `.ts-transport`, `.progress.is-live` / `.is-static`, `.ts-media-btn`):** Clickable progress bar with red `#ef2828` webcam `Live` track and light-grey `#d9d9d9` static image/none track, `24×24` `▶`/`❚❚` media button, status label, and `MM:SS / MM:SS` time display.
6. **Prefix + Input / Slider Composite Control (`.ts-control-box`, `.ts-control-split`, `.ts-slider`, `.ts-reset-inline`, `.ts-dual-controls`):** Split prefix box (`border-right: 1px solid var(--ts-border)`) with right-aligned numeric input plus synchronized range slider (`10×10` cyan thumb) and inline `↺` reset button.
7. **Toggle & Mode Selector Rows (`.ts-toggle-row`, `.ts-mode-row`, `.ts-preset-select`):** Full-width `.button` toggles (`invert color`) with `.is-primary` cyan active state, segmented mode rows, and dark option list styling.
